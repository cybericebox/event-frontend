# Event Frontend DS v2 Migration Implementation Plan

> **Оновлення 2026-09-26:** порядок нижче збережений як початковий аудит користувацьких сторінок. Актуальна послідовність роботи — [`docs/event-admin-first-roadmap.md`](../../event-admin-first-roadmap.md): спочатку оболонка менеджера й базові налаштування події, потім контент та інші адмінські сторінки, після цього користувацькі. Шаблони пошти події відкладено: опубліковані шаблони платформи працюють як резервні. Поточні залежності вже оновлені до Next 16 / React 19 / Tailwind 4; Chakra 2 залишено до заміни старих компонентів.

> **For agentic workers:** Use `superpowers:executing-plans` to implement one reviewed slice at a time. Checkboxes track work; no implementation is authorized by this document alone.

**Goal:** Перевести весь сайт події на затверджені `ds-v2` палітру, компоненти й окремі макети гостя, учасника та Live, зберігши робочі маршрути й підключивши реальні дані.

**Architecture:** `event-frontend` лишається незалежним застосунком: копіюємо потрібні токени, CSS і поведінку з `ds-v2` у нього, без імпорту із сусідньої папки. Спільний кореневий layout задає тему події; оболонка обирається за підтвердженою участю користувача, а не за часом старту. Сторінки мігрують окремими вертикальними зрізами поверх наявних API-хуків; мокові відповіді використовуються тільки для локального перегляду.

**Tech Stack:** Next App Router, React, TypeScript, Tailwind, Radix, TanStack Query, ECharts; ціль після сумісної міграції — Next 16 / React 19 / Tailwind 4, без Chakra.

**Spec:** `../../../docs/EVENT-THEME.md`, `../../../ds-v2/tokens.css`, `../../../ds-v2/guidelines/{principles,color,layout,copy,bans,charts}.md`, `../../../ds-v2/prototypes/event.html`; для Live — `../../../docs/LIVE-CONSTRUCTOR.md`. Перевірена матриця маршрутів і API: `../../event-migration-matrix.md`. Прототип визначає композицію, а API-код — фактичний контракт даних.

## Global Constraints

- Останнє рішення користувача від 2026-09-25: міняємо **і кольори, і макети**. Речення в `PRODUCT.md` / `ds-v2/guidelines/layout.md` про збереження старих макетів для цього етапу застаріло.
- `event-frontend/REDESIGN.md` та липневі `docs/superpowers/specs/*`/`plans/*` описують попередню Indigo Frost / `ds-bundle` реалізацію. З них беремо лише перевірену поведінку й маршрути, не палітру і не композицію.
- Бренд за замовчуванням `#211A52`; світлий фон `#F7F7F9`; темна тема «Сутінки»; окремий `brand` і необов’язковий `accent` події. Акцент підсвічує, не заливає великі площини.
- Гостьовий навбар, вежа учасника, поповери, модалки й Live беруть розміри та стани з `ds-v2`. Немає градієнтної шапки, лівих кольорових смуг, вигаданих балів чи VPN-статусу.
- `ds-v2` — еталон, не runtime-залежність. Фронтенд не імпортує файли з іншого репозиторію/кореня.
- Мова інтерфейсу — українська; назви «Подія», «Завдання», «Прапор», «Розв’язано», «Результати», «Сповіщення» з `ds-v2/guidelines/copy.md`.
- На цьому планувальному етапі збірку, оновлення пакетів і переробку сторінок **не запускати**. Кожен виконаний зріз потім перевіряється в браузері перед переходом до наступного.

## Поточний стан, перевірений 2026-09-25

| Область | Стан у коді | Ціль |
|---|---|---|
| Тема | `src/app/globals.css`: HSL Indigo Frost; `tailwind.config.ts`: старі кольори | Локальна копія токенів `ds-v2`, світла/темна тема і параметри події |
| Оболонка | `src/app/layout.tsx` обгортає **всі** маршрути в `AppShell`; `TopBand` має градієнт і фіктивні `#4 · 1 250`; `Sidebar` має фіктивний «VPN активний» | Гостю — навбар і футер; учаснику — вежа 216 px, верхня панель; лише фактичні дані |
| Вхід на сайт | `/` переспрямовує на `/challenges` за `StartTime`/`FinishTime` | Вибір за підтвердженою участю; фаза керує доступністю дій, а не типом оболонки |
| Завдання | Сторінка й модалка працюють, але стилі та розміри старі | `Плитки` / `Рейка`, центральна модалка, стани з `ds-v2` |
| Результати | ECharts + таблиця, старі кольори й обмеження графіка до топ-5 | Графік топ-10 + своя команда, пошук і керування видимими командами; окремий Live |
| Команда | `/team` на Chakra; `/teams`, `/teams/[id]`, `/cabinet` — заглушки | Повноцінна команда, її деталі, створення/вступ/запрошення, VPN за реальним статусом |
| Контент | `/` — зашитий банер; `/faq` — старий HTML; `/p/[slug]` — заглушка | Лендинг, правила, FAQ, новини й інші сторінки як опубліковані стеки блоків |
| Сповіщення | Дзвоник використовує старий список `/events/self/notifications`, є фіктивна дія «Прочитати всі» | Єдиний стиль платформи, пагінація/прочитання/нові повідомлення за чинним API |
| Стек | Next 15, React 18, Tailwind 3, Chakra v2 | Оновлені сумісні версії та прибраний Chakra після міграції його споживачів |

**Контрактні розриви:** `EventInfoSchema` парсить поля старого API, яких немає в поточному `eventInfoResponse`; там також немає `EventID` і кольорів, а `/events/self/info` захищено `PermSelf`, тому він не може бути надійним джерелом гостьового SSR. У AP Backend є `GET /events/{id}/content` і `/content/pages/{slug}`, а цей фронтенд їх ще не викликає. Перед оболонками створити безпечний публічний спосіб отримати ID, назву, фазу й тему події за доменом. Повний перелік — у `docs/event-migration-matrix.md`. Не підміняти відсутні серверні поля вигаданими продакшн-значеннями.

## Review Focus

1. Гість, авторизований неучасник, учасник до старту, під час і після фінішу бачать правильну оболонку та доступні дії.
2. У світлій і темній темі базова та інша подія з власним `brand/accent` лишаються читабельними без спалаху старої палітри.
3. При недоступному API сторінка лишається на event-домені й показує відновлюваний стан; 401 обробляється окремо від 5xx.
4. Порожні, довгі й помилкові списки завдань/команд/сповіщень не ламають 360 px, клавіатуру та прокрутку.
5. Публічні сторінки не розкривають контент лише для учасників; Live не має інтерактивних підказок чи кнопок під час показу.
