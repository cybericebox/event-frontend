# Быстрая загрузка публичных страниц и актуальные данные события

## Результат

Публичный лендинг и публичные дополнительные страницы сразу получают готовые блоки с сервера фронтенда. Редко меняющиеся документы страниц кэшируются отдельно от значений переменных. Открытая вкладка обновляет живые значения без повторной загрузки конструктора; счётчик продолжает тикать локально. Кнопка регистрации является отдельным действием и не встроена в счётчик. Доступ и возможность регистрации окончательно проверяет AP Backend.

## Границы

- Первый этап охватывает лендинг и публичные дополнительные страницы. Приватные и страницы только для модераторов продолжают получать данные через браузер с авторизацией; их содержимое не попадает в общий кэш.
- Существующий менеджерский API для редактирования остаётся. Новые публичные чтения не принимают пользовательскую сессию и возвращают только разрешённые публичные значения.
- SSE и общий распределённый кэш сейчас не вводятся. Пятиминутное обновление документа допустимо; живые данные имеют отдельную минутную свежесть. Позже сигнал изменения сможет досрочно инвалидировать кэш документов.
- Фронтенды остаются независимыми. Сохраняются текущие пути и правила доступа для дополнительных страниц.

## Данные и кэш

1. AP Backend отдаёт публичный документ страницы отдельно от значений переменных. Документ содержит порядок, типы и настройки блоков, текст, ссылки, условия показа и привязки переменных. Значения переменных в него не встраиваются.
2. Отдельное публичное чтение значений принимает мероприятие и страницу, определяет используемые в её документе переменные и возвращает только разрешённые публичные значения в текущих типах (`string`, `number`, `boolean`, `null`). Приватные значения не возвращаются даже при прямом запросе к API.
3. Сервер фронтенда кэширует документ каждого мероприятия и страницы на 300 секунд, а публичные значения — на 60 секунд. Ключ включает ID мероприятия и идентификатор страницы. Запрос `public-info`, который проверяет наличие и опубликованность мероприятия, остаётся некэшированным до чтения содержимого. Кэш одного контейнера не требуется разделять с другим.
4. На первом ответе сервер рендерит блоки из кэшированного документа и текущего снимка значений. В открытой вкладке значения обновляются раз в минуту, при возвращении фокуса и после восстановления сети через лёгкий публичный запрос к серверу фронтенда. Документ в уже открытой вкладке не перезагружается сам; новая навигация или обновление страницы получают документ по его пятиминутному сроку.
5. При ошибке обновления живых данных уже показанная страница остаётся доступной. Состояние регистрации нельзя считать подтверждённым по просроченному снимку: действие скрывается или становится недоступным до успешного обновления. Изменение переменной повторно вычисляет условия показа блоков и текстовые подстановки без скачка макета целой страницы.
6. Даты начала и завершения, полученные от сервера, задают точные моменты локального переключения счётчика и условий, зависящих только от времени. На этих границах клиент также запрашивает свежие значения. Бэкенд остаётся источником истины при выполнении действия.

## Счётчик и регистрация

- У блока «Зворотний відлік» есть дата начала показа (необязательная), целевая дата и настройка «Приховати після завершення». Каждая дата выбирается из даты события или задаётся вручную с точностью до минуты; существующие варианты оформления сохраняются. Если дата начала не задана, счётчик виден сразу. Если скрытие выключено, после достижения цели он остаётся с нулями. Так можно поставить один блок до старта и другой до завершения.
- Поля `action` и `secondaryAction` удаляются из настройки и отображения счётчика. Кнопки героя также оформляются отдельным блоком действий, чтобы счётчик и поведение кнопки не зависели друг от друга.
- Блок кнопок поддерживает обычную ссылку и действие `join_event`. Для ссылки остаётся выбор встроенной, дополнительной или собственной страницы. Для `join_event` адрес не вводится: переход ведёт в существующий сценарий `/join`, а не вызывает регистрацию прямо из блока. Неавторизованный посетитель проходит вход с возвратом к `/join`.
- Кнопка `join_event` показывается только гостю или пользователю, который ещё не подал заявку и которому регистрация сейчас доступна. Для одобренного, ожидающего решения и отклонённого пользователя она скрыта. Доступность включает режим регистрации и жизненный цикл события; серверная проверка отправки заявки обязательна независимо от видимости кнопки. Если в блоке не осталось видимых кнопок и нет текста, блок не занимает место.
- Изменение статуса участия после отправки заявки сразу обновляет кнопку без перезагрузки страницы. Состояние регистрации обновляется с живыми значениями и на временной границе.

## Быстрый первый показ

- Публичный HTML не ждёт запросов авторизации, статуса участия и команды. Эти запросы уточняют персональные элементы навигации и кнопку регистрации после первого показа, сохраняя уже отрисованные публичные блоки.
- Первичная загрузка публичной страницы обращается к AP Backend за проверкой мероприятия и, при промахе кэша, за документом и значениями. Повторные посетители получают документ из кэша конкретного инстанса. Изображения сохраняют существующие версионные адреса.
- Данные одного пользователя, анкеты и участника не должны появляться в серверном публичном HTML или кэше документа/значений.

## Проверка

1. Два последовательных публичных запроса к одному мероприятию используют один документ в пределах 300 секунд; другое мероприятие и другая страница не смешиваются. Значения пересчитываются в пределах 60 секунд без повторной загрузки документа.
2. Открытая вкладка меняет счётчики каждую секунду; после изменения статистики обновляет подстановки и условия показа без перезагрузки. На старте и завершении события нужный счётчик появляется или скрывается согласно настройке.
3. Изменение документа становится видно после истечения его срока и новой навигации/перезагрузки. Снятие мероприятия с публикации не раскрывает ранее кэшированный документ.
4. Регистрационная кнопка отсутствует у участника и при закрытой регистрации; после входа и заявки меняет состояние. Прямая отправка заявки при закрытой регистрации отвергается бэкендом.
5. Приватная страница по-прежнему требует авторизации и не попадает в публичный кэш. Публичный первый показ не блокируется ожиданием персональных запросов.
6. Профильные проверки API, типов, компонентов и сборка проходят; изменённые файлы коммитятся по завершённым этапам, рабочие деревья остаются чистыми.
