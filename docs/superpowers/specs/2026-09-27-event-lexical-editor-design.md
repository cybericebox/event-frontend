# Lexical для текста страниц и просмотра заданий

## Результат

Конструктор страниц события использует локальную копию актуального Lexical-редактора админки для блока «Форматований текст», ответов FAQ и текста разделов. Панель инструментов, поведение выделения, форматирование, списки, ссылки и вставка Markdown работают как в админке. Вставка переменных сохраняет нынешний выбор переменных события, их фильтрацию, формат даты и жёлтый неделимый бейдж. Тот же локальный компонент в режиме только чтения отображает тексты на странице события и описания заданий участникам.

## Границы и выбор формата

- В `event-frontend` копируются нужные исходники и зависимости Lexical из `admin-frontend`. Импорта из другого фронтенда и общего пакета нет.
- Форматируемое содержимое хранится как сериализованный Lexical JSON. У блока `text` поле `richText` заменяет `markdown`; у пунктов `doc` и `faq` поле `richText` заменяет строковый `value`. У других типов пунктов `value` остаётся обычной строкой.
- Старые Markdown-поля для форматируемого содержимого не читаются и не преобразуются автоматически. В обратной совместимости и миграции данных нет требования. Неформатированные текстовые поля и их `{{event.name}}` остаются строками.
- Сохранение через Markdown было рассмотрено, но отвергнуто: оно теряет часть состояния Lexical, включая формат отдельного бейджа и оформление абзаца. HTML не принимается как формат хранения из-за сложности безопасной проверки.

## Редактор

- В локальной копии остаются Lexical Composer, History, формат текста и блока, заголовки H1–H3, абзац, выравнивание абзаца, оба списка, цитата, код в строке и блоком, ссылка, очистка форматирования, вставка Markdown. Порядок и группировка панели соответствуют действующему редактору админки; визуальные цвета адаптируются к теме события.
- Кнопка переменных остаётся справа в панели форматированного текста. Она открывает текущий выбор переменных события без затемнения; список ограничен доступными значениями. Выбор вставляет `VariableNode` целиком на сохранённую позицию курсора. Узел можно выделить как единое целое и форматировать отдельно; в редакторе он жёлтый и без скобок.
- Ссылка использует нынешний выбор системной страницы, дополнительной страницы или собственной HTTPS/внутренней ссылки. Выделенный текст остаётся выделенным после открытия выбора. Небезопасная ссылка не сохраняется.
- Для переменной даты в конкретном поле остаётся текущий выбор готового или собственного формата. При удалении переменной из документа её формат больше не сериализуется. Названия переменных в меню, подсказки, звёздочки и сообщения ошибок остаются украинскими.

## Хранение и проверка на сервере

- AP Backend принимает объект Lexical в `richText` для трёх указанных мест. Проверяется наличие непустого текста или узла переменной, допустимые типы узлов/форматирования, безопасные адреса ссылок, максимальный размер и глубина документа. Неизвестные узлы и сырое HTML отклоняются до записи.
- Узел переменной сериализуется в совместимой с админкой форме `type: "variable"`, `varName`, `formats`. Имя должно входить в публичный каталог переменных события и в объявленные привязки блока. Значения и секреты в документ не записываются.
- `dateDisplays` по-прежнему привязан к имени поля и имени переменной; сервер проверяет, что соответствующий узел действительно присутствует в этом поле. Прочие блоки и обычные строки продолжают проходить свои текущие проверки.
- Клиентская схема, создание блока, локальные ошибки обязательных полей, сохранение и повторное открытие используют один и тот же JSON-контракт. Временные тестовые данные не остаются на странице после проверки.

## Отображение

- Блоки `text`, `doc` и `faq` используют общий режим только чтения для Lexical JSON. Он выводит текст через React/зарегистрированные узлы, без вставки доверенного HTML. Подстановки переменных берутся из актуальных значений события; формат даты и оформление узла применяются и в боковом превью, и на странице модератора/посетителя.
- Отображение описания задания в `event-frontend` использует этот же компонент в режиме только чтения вместо собственного обходчика JSON. Узлы переменных задания показываются тем же визуальным элементом; их значение берётся только из разрешённых данных задания. Если значение не передано, отображается понятное имя узла, без редакторских действий и без раскрытия служебных данных.
- Страница заданий, конструктор и публичные страницы должны одинаково показывать списки, заголовки, ссылки, цитаты, код, выравнивание и формат отдельных переменных. Ссылки допускают только безопасные адреса.

## Порядок реализации и приёмка

1. Локально перенести Lexical-узлы, редактор и режим только чтения; установить те же основные пакеты Lexical, что в админке. Сохранить существующий интерфейс выбора переменных и ссылок события.
2. Изменить клиентский и серверный контракт `richText`, серверную проверку и локальные ошибки; обновить фикстуры и тесты для нового контракта без веток чтения Markdown.
3. Подключить редактор к трём полям конструктора, затем общий просмотрщик к превью, страницам события и описанию задания.
4. Проверить вставку и форматирование отдельного бейджа, вставку Markdown, ссылку, дату, отмену/повтор, пустое поле, сохранение и повторное открытие каждого из трёх мест. Сравнить превью и страницу модератора, затем проверить просмотр задания без панели редактирования. Запустить типизацию, линтер, профильные тесты и собрать фронтенд. Каждый завершённый и проверенный этап закоммитить; рабочие деревья оставить чистыми.
