# Міграція event-frontend: маршрути, стани й дані

Актуальна черга сторінок: [`event-admin-first-roadmap.md`](event-admin-first-roadmap.md). Ця матриця описує переважно гостьові та учасницькі маршрути; їх перенесення йде після налаштування події через `/manage`.

Матриця користувацьких маршрутів складена під час початкового аудиту й уточнюється перед перенесенням кожного екрана. Візуальний еталон: `ds-v2/prototypes/event.html`, `ds-v2/tokens.css`, `docs/EVENT-THEME.md` і `docs/LIVE-CONSTRUCTOR.md` у корені CyberICEBox. Старий `REDESIGN.md` описує іншу палітру й не визначає цільовий вигляд. Залежності вже оновлено до Next.js 16, React 19 і Tailwind CSS 4; Chakra UI 2 залишено лише для старих компонентів до їх заміни.

## Принцип маршрутизації

Оболонку визначає **підтверджена участь**, а не час старту. Гість і авторизований користувач без схваленої участі бачать гостьовий навбар. Схвалений учасник бачить вежу 216 px. Фаза події змінює доступність дій усередині сторінок, але не оболонку. Запит із невизначеним статусом участі спочатку показує нейтральний стан завантаження; збій API не переводить користувача на ID-домен.

| Маршрут | Гість / учасник ще не схвалений | Схвалений учасник | Фаза й видимість | Дані та цільовий екран |
|---|---|---|---|---|
| `/` | Публічний лендинг з навбаром, дією входу/приєднання | Лендинг лишається доступним; початкова дія веде до завдань | До старту, під час і після — лендинг не зникає | Опублікований `Landing` з конструктора блоків; не банер + HTML зі старого `EventInfo` |
| `/p/[slug]` | Лише публічні сторінки | Публічні та дозволені учаснику сторінки | Видимість визначає сервер; недоступна сторінка — 404 | `Page` і `Variables` з content API, спільний рендерер блоків |
| `/faq` | Доступна, якщо є опублікована сторінка питань | Те саме | Жодного старого HTML з `Rules` | Канонічна сторінка конструктора або редирект на її slug |
| `/challenges` | Запрошення приєднатися або стан обмеженого доступу | Завдання, категорії, модалка, прапор | До старту — відлік; під час — розв'язання; після — перегляд за серверним дозволом | Новий API переліку завдань і submit; плитки/рейка з `ds-v2` |
| `/scoreboard` | Публічні результати лише за `Public` | `Private` і `Public`; при `Hidden` — пояснення | До старту/без результатів — окремі стани | Snapshot `/events/{id}/results`, топ-10 + своя команда, таблиця; Live окремо |
| Live (новий маршрут) | Лише якщо результати публічні | За видимістю результатів | Повноекранний 16:9/16:10/4:3, без інтерактивних підказок | Snapshot + `/events/{id}/results/live` SSE; `Live` конфіг з content API |
| `/team`, `/cabinet` | Пояснення доступу / вхід | Командний кабінет або індивідуальний стан | У командному режимі створення/вступ; VPN лише за фактичним станом | `/events/{id}/teams/mine`, labs/VPN; один канонічний маршрут, другий — редирект |
| `/teams`, `/teams/[id]` | Лише дані, дозволені налаштуванням видимості | Список і деталь за правами | Порожній/закритий список — чесний стан | Потрібно перевірити/додати публічний read API; зараз обидва екрани — заглушки |
| Дзвоник у дозволеній оболонці | Без авторизації прихований | Список і лічильник | Нові повідомлення після відкриття сторінки — тост; старі — тільки в списку | `/notifications/inbox` + `/poll`, курсорні порції; жодного фіктивного «Прочитати всі» |

## Критичні розриви контракту

Це початковий перелік, а не поточний стан кожного пункту: публічний `/events/self/public-info` вже підключено в `src/api/publicEventInfo.ts`, а тема — у `src/app/layout.tsx`. Решту рядків треба перевірити безпосередньо перед роботою над відповідною сторінкою.

| У фронтенді зараз | У AP Backend зараз | Необхідний крок до перенесення екрана |
|---|---|---|
| Серверний і клієнтський `/events/self/info` парситься як `Description`, `Rules`, `Picture`, `Type`, `ScoreboardAvailability`, обов'язковий `FinishTime` | DTO дає `PreviewDescription`, `PreviewPicture`, `ScoreboardVisibility`, nullable `FinishTime` і `Participation`, `Status`; `EventID` з use case у DTO не потрапляє | Узгодити DTO/schema, надати event ID; старі контентні поля не відновлювати вигаданими даними |
| `/events/self/info` використовується для серверного рендеру гостя | Маршрут зареєстрований з `PermSelf`; без сесії гість не має гарантованого доступу | Додати/відкрити безпечний публічний event-info за доменом з мінімальним DTO; перевірити tenant resolution без клієнтського Origin. До цього не робити гостя залежним від приватної ручки |
| `GET /events/self/join?noRedirect=true` | `POST /events/self/join` | Перенести метод і обробку статусів |
| `/events/self/teams/*`, старий `/vpn-config` | `/events/{id}/teams/*`, `teams/mine`, `teams/labs/vpn` | Перекинути хуки та DTO після отримання event ID; не малювати фальшивий VPN статус |
| `/events/self/challenges/info`, `/solvedBy`, `/solve` | `/events/{id}/teams/challenges/mine` і `/submit`; окремо перевірити публічний каталог завдань, файли/підказки | Зіставити реальні DTO й видимість перед міграцією модалки |
| `/events/self/score` з локальним top-5 | `/events/{id}/results`, `/live`, `/results/team`; сервер перевіряє видимість | Перейти на snapshot + SSE, не обходити `Hidden/Private/Public` клієнтським фільтром |
| `/events/self/notifications`, локальний список | `/notifications/inbox`, `/inbox/poll`, `/inbox/{id}/read`, `/inbox/read-all` | Використати чинний inbox-контракт і ліміт 10 на порцію |
| Старий `EventInfo` не має кольорів | `EventConfig` і `eventInfoResponse` ще не містять `brand`, `accent`, трьох читабельних акцентів і `theme_version` | Додати збереження/валідацію в AP Backend, віддати чотири CSS-входи в публічному DTO, виставити їх на `<html>` |
| `/p/[slug]`, `/teams`, `/cabinet` — заглушки | Content read API є; публічний список/деталь команд потребує окремої перевірки | Не заміняти заглушки декоративними картками без даних |

## Фіктивні значення, які треба прибрати

- `TopBand`: градієнт старої палітри, `Jeopardy CTF`, місце `#4` і `1 250` балів.
- `Sidebar`: постійно зелений `VPN активний` і пункт `Сторінка` без маршруту.
- `AvatarMenu`: ім'я `Учасник` та `PROFILE_HREF="#"`.
- `NotificationsPopover`: джерело старого API й кнопка прочитання без операції.
- `/`: редирект за годинником, старі `Description`/`Picture`, HTML через `dangerouslySetInnerHTML`.
- `/scoreboard`: локальний топ-5 і клієнтська перевірка старого `ScoreboardAvailability`.

## Порядок приймання

Пункти нижче — умови приймання користувацьких маршрутів **після** адмінських зрізів із актуальної черги.

1. До перенесення сторінок — публічне визначення події за доменом, узгоджені DTO і збережена тема; дві теми з базовим та іншим брендом без миготіння старої палітри.
2. Потім — локальні `ds-v2` токени й примітиви, гостьова й учасницька оболонки, усі маршрути по черзі. Новий візуальний компонент має брати кольори тільки з токенів.
3. Для кожного маршруту — desktop 1440 px і mobile 360 px, світла й темна тема, гість/несхвалений/учасник, доступ/403/404/5xx, порожні та довгі дані. Окремо перевірити start/finish і `Hidden/Private/Public`.
4. Після перенесення сторінок — повна перевірка маршрутів і збірки на оновленому стеку. Сама успішна збірка не підтверджує правильний дизайн.

Скріншоти поточного UI й еталону залишаються окремим кроком перед зміною оболонки: нинішні сторінки не слід використовувати як джерело композиції.
