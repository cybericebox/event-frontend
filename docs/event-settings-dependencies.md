# Параметри події: порядок і залежності

Стан на 2026-09-26. Це карта для наступних екранів, а не твердження, що всі обмеження вже реалізовані. Джерело полів: `AP Backend/internal/model/eventConfig/config.go`, `internal/model/event/lifecycle.go`, `internal/useCase/event/input.go`, `internal/model/eventContent/page.go`.

## Порядок для менеджера

1. **Підготовка `/manage`:** формат участі, для команд — обраний максимум і необов’язковий мінімум учасників, режим реєстрації, час публікації, час початку, період приєднання. Без формату сервер не дає зберегти розклад; до публікації реєстрація заборонена незалежно від режиму реєстрації.
2. **Основне:** назва, режим реєстрації, командні ліміти, тема, короткий опис та зображення для прев’ю.
3. **Контент:** окремий конструктор головної, окремий список і конструктор сторінок зі slug, видимістю та місцем у навігації. Зараз реалізований лише редактор головної, а сервер уже підтримує CRUD сторінок.
4. **Змагання:** групи завдань, прикріплені версії вправ, варіант, бали, підказки, передумови, порядок і публікація; окремо профіль нарахування балів.
5. **Проведення:** учасники, команди, анкети, спроби розв’язання та рішення модератора; результати й Live. Налаштування видимості результатів і списку учасників належать сюди, а не до початкової форми.

## Коли обмежувати зміни

| Поле / група | Поточне серверне правило | Етап і дія |
|---|---|---|
| Формат участі | Можна змінити до `PublishAt`; після першої публікації заблоковано. Опублікований `PublishAt` не переноситься. | **Реалізовано.** Фіксуємо раніше, ніж з’являться учасники чи команди. Скасування публічності не розблоковує поле. |
| Дата публікації | До публікації змінюється; після — незмінна. | **Реалізовано.** Інакше подію можна було б формально повернути в стан «ще не опубліковано» й обійти блокування формату. |
| Дата старту, фініш, закриття, період приєднання | Сервер перевіряє порядок дат і стан інфраструктури, але дозволяє правки пізніше. | До старту дозволити редагувати. Після старту окремо визначити правила ручного завершення та зміни майбутнього фінішу; не зсувати старт у майбутнє після фактичного початку без спеціальної операції. **Потрібне серверне обмеження.** |
| Режим реєстрації | `closed` / `approval` / `open` застосовується до нових заявок; наявні записи лишаються. | Дозволити зміну після публікації: це керування майбутніми заявками, але показувати наслідок для наступних реєстрацій. |
| Максимум і мінімум учасників у команді | Обираються на першому етапі та блокуються після першої публікації. | **Реалізовано.** Після появи команд ці ліміти змінювати ризиковано; зберігаємо просте й перевірне правило першої публікації. |
| Максимум команд | Перевіряється при наступному створенні; сервер поки не звіряє новий ліміт з уже створеними командами. | Перед зменшенням перевіряти фактичну кількість команд; не дозволяти значення нижче поточного стану. **Потрібне серверне обмеження.** |
| Назва, тема, прев’ю, текст головної та сторінок | Зміни дозволені; видимість сторінки перевіряє API. | Залишити редагованими, оновлювати публічний кеш; приватна сторінка не повинна потрапляти в анонімний рендер. |
| Профіль балів, бали завдань, варіанти вправ | Окремі API; частина змін може зачепити вже записані розв’язання. | До першого розв’язання — вільна настройка. Після — або контрольований перерахунок з журналом, або заборона небезпечної зміни. **Окремий аудит перед UI.** |
| Видимість результатів і учасників | `hidden` / `private` / `public`, читаючий API застосовує права. | Можна змінювати, але після звуження доступу негайно не віддавати старий публічний кеш. |

`AvailableFrom` і `ArchiveAt` — вікно існування домену, яким керує глобальна адмінка. Воно не замінює `PublishAt` / `StartAt` у локальних налаштуваннях події.

## Доступ до сторінок

Публічні `/` та `/p/[slug]` сервер рендерить анонімно заради SEO. `GET /events/self/public-info` кожного разу перевіряється без кешу; лише після успішної публічної перевірки головний контент кешується до 60 секунд за ID події. Це не дає видати старий кеш після закриття події на новому серверному запиті. Неопубліковані сторінки менеджер отримує в браузері з API-кукою через `manage/content` і `manage/pages/{slug}`. Опубліковані сторінки з обмеженням для учасників також догружаються в браузері. Повне наскрізне випробування на реальній сесії й перевірка клієнтського кешу Next після відкликання публікації ще потрібні.
